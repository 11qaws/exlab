# exlab

exlab은 하나의 실용적인 운영 셸에서 `Roulette`와 `Showdown`을 선택해 실행하는 게임 도구입니다. 현재 버전은 `1.3.5`입니다.

## 1.3.5 헤더 스트리머 테마 선택

- 5개 스트리머 테마 선택을 공통 설정 패널에서 공통 헤더 우상단으로 옮겨 게임 선택과 나란히 배치했습니다.
- 프로필 이미지만 보이는 32px 원형 라디오로 한 번에 전환하며, 모바일에서는 24px로 축소해 게임 선택과 함께 한 줄을 유지합니다.
- 테마 상태와 저장 책임은 공통 셸에만 두고 게임 adapter의 중복 테마 전달값과 각 게임 설정 패널의 중복 선택 UI를 제거했습니다.
- 원형 선택기는 키보드 라디오 조작, 스트리머별 접근성 이름, 고대비 선택 링을 유지합니다.

## 1.3.4 GitHub Pages 정적 미러

- 기본 Vinext·Sites 빌드와 분리된 클라이언트 전용 진입점으로 같은 `ExlabApp`을 `/exlab/` 경로에 빌드합니다.
- Roulette와 Showdown의 지연 로딩, 공통 명단, 동일 이름 정책, 스트리머 테마와 로컬 저장 상태를 공개 Pages에서도 그대로 사용합니다.
- GitHub Actions가 생산 빌드와 117개 회귀 테스트를 통과한 뒤 정적 산출물을 검증하고 Pages에 배포합니다.
- 배포 검증은 `/exlab/` 자산 기준 경로, 두 게임의 동적 청크, `.nojekyll`, OG 이미지와 다섯 스트리머 프로필 이미지의 존재를 확인합니다.
- GitHub Pages는 공개 미러이며, 인증된 비공개 Sites 배포와 별개로 운영합니다.

## 1.3.3 인게임 결과 UI 통합 범위

- 게임 무대와 결과 레일을 결과 발표 전후에 계속 마운트하는 `Continuous Stage + Result Dock` 구조를 적용합니다.
- Showdown은 별도 결과 페이지로 전환하지 않고 RaceCanvas 위에서 승자 Hero를 공개하며, 기존 라이브 순위 레일이 도착 결과 레일로 이어집니다.
- Roulette은 원판과 다트를 유지한 채 당첨자 Hero가 게임 무대에서 오른쪽 최신 결과 행으로 이동합니다.
- 결과 계산과 표현 생애주기를 분리하고, 오래된 `runId`·`presentationId` 이벤트가 현재 연출을 바꾸지 못하게 합니다.
- 결과 공개 뒤에도 Showdown 미도착 마블과 골인 시간이 동일 화면에서 계속 갱신됩니다.

## 기존 통합·안정화 범위

- 공통 헤더의 게임 레지스트리에서 Roulette와 Showdown을 전환합니다.
- 공통 헤더의 `참가자 N명` 버튼에서 공유 명단 대화상자를 열며, 저장한 명단은 Roulette와 Showdown에 동시에 반영됩니다.
- 동일 이름 정책도 두 게임이 공유합니다. 기본값은 미허용이고, 허용하면 같은 이름의 각 입력 행을 삭제하거나 합치지 않고 서로 다른 참가 번호로 유지하며 선택값을 저장합니다.
- 두 게임은 `exlab:roster:v1` 공유 명단을 사용하며, 게임별 가중치·상품·조 편성·물리 설정은 서로 섞지 않습니다.
- 마지막으로 사용한 게임과 5개 스트리머 테마를 브라우저에 보존합니다. 공통 셸은 실용적인 라이트 기반을 유지하면서 선택한 프로필의 색을 제품 chrome에 적용합니다.
- Showdown 코스만 게임 전용 라이트·다크 맵 토글을 제공하고 기본값은 라이트입니다.
- 실행 중에는 게임 전환을 잠그고, 준비 상태로 돌아온 뒤 다시 전환할 수 있습니다.
- 최초에는 마지막으로 선택한 게임만 지연 로드합니다. 방문한 게임 화면은 이후 keep-alive로 마운트 상태를 유지해 전환 전 설정 초안을 보존하고, 비활성 게임에는 `active=false`를 전달해 미리보기·타이머 같은 지속 작업을 일시 정지합니다.
- 새 게임은 catalog와 공통 adapter 계약을 등록하는 방식으로 추가합니다.
- Showdown 준비 화면의 큰 홍보형 제목·장문 소개를 제거하고 게임 설정, 미리보기, 주 행동만 남겼습니다.
- 기존 Showdown(Race 레거시) 명단은 새 공통 명단이 없을 때 한 번 가져오고, 이후 공유 명단을 저장할 때 `marble-game:roster`에도 함께 기록해 이전 버전으로 롤백할 수 있게 합니다. 별도 origin의 Roulette 저장소는 자동 이전하지 않습니다.
- Showdown과 Roulette 스타일은 각각 `.showdown-game`, `.roulette-game` 범위로 격리합니다. 공통 셸은 모든 하위 서체를 `Inter` → `Pretendard` → 시스템 산세리프로 덮어써 하나의 타이포그래피를 유지합니다.
- Showdown의 스코프 루트 스타일을 복구해 라이트 맵에서도 방송 프레임과 순위표 대비를 유지하며, 데스크톱 준비 화면은 뷰포트 안에 고정하고 긴 설정만 패널 내부에서 스크롤합니다.

자세한 공통 상태·저장·게임 adapter 계약은 [EXLAB_PLATFORM_SPEC.md](./EXLAB_PLATFORM_SPEC.md)를 참고하세요.

## Showdown

전체 명단을 조당 최대 10명으로 균형 편성한 뒤, 선택한 조의 마블이 시드로 만든 불규칙한 가로 배치에서 동시에 출발해 Matter.js 물리 코스를 통과합니다. 우승자를 먼저 정하는 모드는 없으며, 출발 전에 참가자를 익명 슬롯에 한 번 배정한 뒤 실제 결승 통과 순서만으로 결과를 결정합니다.

1.3.5는 1.2.3의 Showdown 물리·라이브 시계·골인 기록 계약을 변경하지 않습니다. 현재 시간은 화면이 보여주는 소수 물리 프레임을 따라가므로 FINAL MIX 슬로모션에서도 장면과 어긋나지 않으며, 당첨자 기록은 최초 결승 통과 프레임에서 고정됩니다.

## 구현 범위

- 전체 명단 최대 320명, 조당 2~10명
- 전체 인원에 맞춘 최소 조 수 자동 보정과 더 작은 조 선택
- 동일 이름 기본 미허용, 운영자 옵션으로 별도 참가 허용
- 1명 이상 N명 당첨 설정과 당첨 기준·포디엄 기준을 분리한 경기 유지
- `podiumCount = min(3, 참가자 수)`, `resultGateCount = max(winnerCount, podiumCount)`로 계산하고, 결과 게이트 인원이 화면에 모두 도착한 뒤 3초간 경기 화면을 유지한 다음 결과 전환
- 결과표를 연 뒤에도 미도착 순위는 공란으로 두고, 전체 물리 프레임을 계속 재생하며 도착 순서대로 실시간 입력
- 결과 진입 시 같은 `runId`의 최소 기록을 한 번 저장하고, 추가 도착자가 생길 때만 해당 기록을 갱신해 프레임마다 중복 이력을 만들지 않음
- `createRaceSlotAssignment`로 시뮬레이션 전에 참가자·출발 슬롯 대응을 확정하고, `RaceSimulation`이 그 매핑을 결과까지 보유하는 재현 가능한 Matter.js 물리 시뮬레이션
- `layoutSeed`로 익명 슬롯의 x좌표에 ±12px 지터를 주되 평균을 0으로 맞추고, y좌표·동시 해제·최소 36px 간격을 유지하는 불규칙 출발 배치
- 결과·당첨자·참가자 신원을 참조하는 힘, 선두 감속, 속도 덮어쓰기, 횡풍, 공간 힘장은 사용하지 않음
- 미도착 후미 마블에만 +y 방향으로 적용되는 제한형 추격 가속: 600px부터 부드럽게 시작해 1,000px에서 2위는 기본 중력의 25%, 최하위는 32%에 도달하고, 선두를 따라잡는 속도가 600px/s에 이르면 0까지 감쇠
- 기존 속도감을 유지한 채 세로 길이를 13,500px로 확장한 약 30초 코스
- 경기 구간 폭 366~774px, 중심선 x=250~660의 10개 직선 구간과 좌우 이동량이 큰 9개 S자 전환부, 4개 360° 회전 장치
- 25% 단위로 `PIN DROP → BUMPER RUN → SQUEEZE GATES → FINAL MIX`의 장애물 밀도와 구성을 바꾸고 구간 경계를 경기 화면과 미리보기에 표시
- Matter 충돌 법선과 반발계수만 사용하는 막대형 범퍼. 별도 위치·속도 덮어쓰기나 순위 기반 충격은 사용하지 않음
- 60Hz 경기 스텝을 두 번의 120Hz 물리 서브스텝으로 계산해 빠른 마블의 벽 터널링을 방지하고, 외곽 경계 이탈을 좌표 보정으로 숨기지 않음
- 범퍼 반발계수 `1.22~1.32`, 회전 막대 반발계수 `0.68~0.80`과 상향된 회전 속도
- 일부 직선 벽을 범퍼와 같은 반발계수로 설정한 탄성 벽 구간
- 장애물 성격을 색으로 구분하는 공용 5색 체계: 핫핑크=범퍼, 레몬=핀, 민트=가이드, 스카이=탄성 벽, 라벤더=회전 막대
- 코스 바탕은 라이트 모드가 기본이며 다크 모드를 선택 가능. 장애물의 의미 색상은 두 모드에서 동일
- 결승 직전 `한쪽 위험 범퍼 → 벽 방향 회전 막대 → 완만한 수축부 → 내부 폭 60px 결승 통로` 구조
- 위험 범퍼나 회전 막대에 우연히 걸린 선두만 잠시 지연되고, 다른 마블은 항상 최소 3개가 나란히 통과할 수 있는 우회 폭을 확보
- 최종 결승 회전 막대 폭 244px, 위험 경로 점유율 상한 60%. 실제 위험 점유율은 57.83%이고 상시 우회 폭은 159.59px, 마블 지름 기준 5.32개
- 핀·섬·선반·회전 바는 직선 구간에만 배치하고, 모든 경기용 직선 구간의 좌·우 벽에 최소 1개씩 중앙 유도 디플렉터가 있는지 자동 검증
- 모든 독립 충돌체 사이에 공 지름 30px보다 넓은 36px 최소 통과 폭을 강제하는 코스 검증기
- 회전 막대는 전체 회전 반경 대신 중심축에 반지름 15px 공 하나가 놓인 것으로 검사하며, 회전 팔이 주변 오브젝트 가까이 지나가는 것은 허용
- 40초 이후에만 전원에게 같은 비율로 적용되는 시간초과 방지 중력 상승. 참가자·순위·결과와 무관
- 동일 경기 재생, 새 경기 생성, 최근 결과 20개 로컬 저장
- 데스크톱 전체 순위와 모바일 상위 3명 실시간 순위. 제목에는 현재 물리 경기 시간, 각 행에는 미도착 `—` 또는 최초 결승 통과 프레임의 `MM:SS.cc` 골인 시각을 표시하고, 순위 교체를 0.2초 위치 전환으로 연결. 결과 발표의 당첨자 카드와 도착 순위에도 같은 골인 시간을 유지하며, 모바일에서는 첫 3행 밖에 있더라도 현재 가장 앞선 미도착 경쟁자를 항상 추가 표시
- 세로 가속도를 적용한 선두 추적 카메라, 0.5초 선두 변경 확인, 카운트다운, 효과음, reduced-motion 대응
- 실제 물리 이벤트로만 작동하는 지속 선두 교체, 접전, 결승 접근, 포토 피니시, 속도 트레일 연출. 다중 당첨 경기에서는 결과 게이트가 충족될 때까지 미도착 경쟁자 사이의 선두 교체를 계속 감지
- FINAL MIX(진행률 75~100%)에서 첫 완주 전 전체 1·2위 사이에 발생해 6프레임·15px 조건으로 확인된 역전만 실제 `holdStartFrameIndex` 기준 0.3초 전부터 0.2초 후까지 0.5배속·100% 확대(2.0배)로 강조하고, 겹치면 최신 이벤트로 0.5초를 갱신
- reduced-motion에서는 정상 속도·무확대 정적 큐만 표시하며 시네마틱은 물리 프레임과 결승 순서를 바꾸지 않음
- 매 프레임 바뀌는 거리·시간 수치는 `aria-live`에서 제외하고 지속 선두 교체·접전·결승 접근·포토 피니시 같은 사건만 보조 기술에 알림
- 라이트·다크 양쪽에서 공용 5색 장애물의 경계가 배경과 분리되도록 테마별 외곽선 적용
- 같은 경기 다시 보기에서 카메라와 일시 연출 상태를 함께 초기화하는 재생 에포크
- `3 → 2 → 1 → GO` 출발과 준비 화면의 10초 실제 물리 미리보기
- 준비·생성·방송 대기·경기·결과·오류 상태를 분리한 독립 실행 흐름

## 물리 결과 계약

Showdown에는 결과 선확정 모드가 없습니다.

1. 경기 생성 시 `createRaceSlotAssignment`가 `raceSeed`로 참가자와 익명 출발 슬롯의 대응을 한 번 정합니다.
2. `raceSeed`로 모든 참가자에게 공통인 물성·회전 장치 변형을 정하고, `layoutSeed`로 익명 슬롯별 ±12px x 지터를 만듭니다. 지터 평균은 0, y좌표는 동일하며 마블 간 최소 거리는 36px입니다.
3. 확정 매핑을 `simulateRace`에 전달하고 `RaceSimulation.slotToCandidateId`에 복사해 물리 프레임과 참가자 대응의 단일 근거로 사용합니다.
4. 경기 중 참가자 ID, 이름, 색상, 당첨자, 예정 결과를 읽어 힘을 바꾸지 않습니다. 실시간 거리와 미도착 순위는 공개된 제한형 추격 가속에만 사용합니다.
5. 추격 가속은 후미 마블의 +y 힘만 더하며 선두를 늦추거나 마블 속도를 덮어쓰지 않습니다.
6. 범퍼·회전 막대·탄성 벽은 Matter의 접촉 법선과 반발계수로만 공을 튕깁니다.
7. 실제 결승선 통과 순서가 당첨자와 최종 순위를 결정합니다.

같은 두 시드는 같은 배치와 물리 프레임을 재현하지만, 어떤 슬롯이나 참가자의 승리를 보장하지 않습니다.

## 현재 설계 기준

결승부의 목표는 “모두를 붙잡아 무작위로 다시 뽑기”가 아니라, 한쪽 위험 경로를 탄 선두가 잠깐 머뭇거리는 동안 열린 우회로의 후속 마블이 통과할 수 있게 하는 것입니다. 제한형 추격은 큰 격차의 후미 마블만 보조하며 결과를 참조하거나 선두를 늦추지 않습니다. 결승 진입 순위와 최종 순위의 상관관계, 선두 우승률, 격차 분포, 위험 장애물 접촉 에피소드를 함께 회귀 지표로 관리합니다.

자세한 테스트 결과와 설계 결정은 [DESIGN_FINDINGS.md](./DESIGN_FINDINGS.md), 물리 변화 후보와 적용 기준은 [GAMEPLAY_VARIATION_DESIGN.md](./GAMEPLAY_VARIATION_DESIGN.md), 전체 명단·조 편성·풀 패키지 계약은 [EXLAB_SHOWDOWN_SYSTEM_SPEC.md](./EXLAB_SHOWDOWN_SYSTEM_SPEC.md)를 참고하세요.
