# exlab

exlab은 하나의 실용적인 운영 셸에서 `Roulette`와 `Showdown`을 선택해 실행하는 게임 도구입니다. 현재 버전은 `1.3.32`입니다.

## 1.3.32 숨은 참가자 고유색 호환

- 공개 테마 선택, 프로필 자산, 기본 참가자와 미리보기 예시는 아모레또·유레카·세나 아르벨·망징이 4인 체계를 그대로 유지합니다.
- 사용자가 참가자 이름으로 `토로리`, `코코`, `토로리 코코`를 직접 입력한 경우에만 기존 하늘색 마블을 적용하는 숨은 호환 규칙을 복원했습니다.
- 공백·유니코드 정규화 변형도 같은 별칭으로 인식하고, 해당 참가자가 있을 때 다른 참가자에게 하늘색이 중복 배정되지 않도록 회귀 테스트를 추가했습니다.

## 1.3.31 4인 테마 체계

- 공용 테마를 아모레또·유레카·세나 아르벨·망징이 4인 체계로 재편하고, 선택창·현재 테마·프리로드 명세에서 제외된 테마와 프로필 자산을 제거했습니다.
- Roulette와 Showdown의 최초 미리보기 명단도 `레또`, `레카`, `세나`, `망징` 4명으로 맞추고, 제외된 이름의 Showdown 고유색 매핑을 일반 참가자 배색으로 되돌렸습니다.
- 세로형 120px 테마 카드는 유지하면서 선택창 높이를 4장에 맞게 압축했습니다. 이전 버전에서 저장된 더 이상 유효하지 않은 테마 ID는 기본 아모레또 테마로 안전하게 폴백합니다.

## 1.3.30 구조 정리 (기능·화면 변경 없음)

- 두 게임을 같은 층위에 두었습니다. `app/marble`을 `app/games/showdown`으로 옮겨 Roulette와 대칭을 맞췄습니다. 저장 키 `marble-game:roster`는 이전 버전 롤백 경로라 그대로 유지하므로 기존 명단·테마 선택은 영향받지 않습니다.
- 공통 셸에 크기 눈금(타입·간격·radius·컨트롤 높이)을 도입했습니다. 이전에는 의미색만 있고 기준 단계가 없어 화면마다 절대값을 다시 재야 했습니다. 단계는 이 저장소가 실제로 쓰던 값의 분포에서 뽑았고, 96개 선언을 옮기면서 조정 폭은 모두 2px 이내입니다.
- 전체 높이 계산의 주인을 한 곳으로 모았습니다. 헤더 높이 뺄셈이 4개 파일 15곳에 흩어져 있던 것을 셸의 `--exlab-stage-min-height` / `--exlab-stage-height-dynamic`로 통일했습니다.
- 게임 본체 앞부분의 순수 로직(타입·명단 파싱·감사 레코드·연출 reducer)을 각 게임의 모듈로 분리했습니다. 참가자 ID와 후보 핑거프린트가 이동 전과 같은 값을 내는지 회귀 테스트로 고정했습니다.
- 쓰지 않던 DB 템플릿 잔여물과 인증 코드를 제거하고, 스펙·감사 문서를 `docs/`로 옮겼습니다. 테스트는 빌드 없이 돌아가고(`npm test`), CI는 `npm run test:ci`를 씁니다.

## 1.3.29 테마 프로필 선로딩

- 초기 HTML에서 스트리머 프로필 5장을 높은 우선순위로 동시에 요청하고, 앱 부팅 중 `decode()`까지 완료해 테마 선택창이 열린 뒤 사진이 늦게 나타나는 현상을 제거했습니다.
- 디코딩된 이미지 객체를 앱 세션 동안 유지해 테마 창을 다시 열 때도 플레이스홀더가 번쩍이지 않게 했습니다.
- 첫 방문의 이미지 응답 중에는 `테마 이미지 준비 중…` 상태를 표시하고, 재방문 게임 화면은 이를 기다리지 않습니다. 실패·오프라인에서는 8초 뒤 문자 프로필로 안전하게 계속할 수 있습니다.
- Sites 루트와 GitHub Pages `/exlab/` 모두 자산 명세에서 정확히 5개 preload URL을 생성하고 중복·경로 오류를 자동 검사합니다.

## 1.3.28 한 화면 설계 프레임과 Roulette 높이 복구

- 너비 641px·높이 600px 이상 설계 화면은 공통 헤더 아래 한 프레임에 고정하고, 기본 설정 상태에서 문서와 설정 패널에 별도 스크롤이 생기지 않도록 밀도를 조정했습니다. 작은 화면과 낮은 가로 화면에서는 입력을 억지로 축소하거나 자르지 않고 자연스러운 단일 열 흐름을 유지합니다.
- Roulette의 공통 셸부터 미리보기 디렉터까지 높이 소유권을 연결해, 멈추기·결과·설계 전환에서 휠 영역이나 바깥 프레임이 접히던 문제를 막았습니다. 중복 명단 상태가 만들던 빈 공간도 제거했습니다.
- Showdown 참가자는 한 줄에 5명씩 표시하고, 용도가 불분명한 `새 배치`와 중복 명단 편집 동작을 제거했습니다.
- 공통 주 행동과 숫자 스테퍼를 가로 5px 넓히고, 설정 유형별 간격은 유지해 버튼과 값이 답답해 보이지 않도록 정리했습니다.

## 1.3.27 공통 설계 화면과 옵션 유형 정렬

- Roulette와 Showdown이 하나의 참가자 스냅샷과 게임 수명주기 계약을 공유해, 게임을 바꿔도 명단과 참가자 ID가 유지됩니다.
- 두 설계 화면은 같은 준비 상태·주 행동·미리보기·세부 설정 프레임을 사용합니다.
- 필수 설정과 세부 설정 각각에서 옵션을 `텍스트 → 선택형 → 숫자형 → 토글형` 순서로 모으고, 같은 유형의 높이·열 구조를 통일했습니다. 큰 숫자는 정렬된 중앙 칸에서 직접 입력할 수 있습니다.
- 데스크톱은 설정 영역만 스크롤하고 미리보기와 하단 행동을 한 화면에 유지하며, 모바일은 중첩 스크롤 없는 단일 흐름을 사용합니다.

## 1.3.26 Roulette 결과 판독·세션 종료 복원

- 최종 `WIN!` 이름표와 경계 후보 카드를 휠 포인터보다 높은 전용 판독 레이어로 옮겨, 핀이 당첨자 이름을 가리지 않게 했습니다.
- 다트가 조각 경계에 닿는 순간 `경계선!` 충돌 연출을 복원하고, 최종 양쪽 후보 카드가 나타나기 전에 사라지도록 분리했습니다.
- 목표를 달성한 추첨에서 설계 화면으로 돌아오면 세션을 실제로 종료하고, 공개 결과가 기록에 남았다는 안내를 표시합니다. 완료 결과를 일시정지 세션으로 다시 여는 경로는 제거했습니다.
- 미완료 세션의 `세션 종료` 버튼은 고정 빨강 대신 현재 스트리머 테마의 잉크·강조색을 사용합니다.

## 1.3.25 Roulette 색상·이름표와 테마 확정 연출

- Roulette 조각에서 의도하지 않은 `#1`, `#2` 번호표를 제거하고, 공간이 충분할 때만 참가자 이름을 표시합니다.
- 스트리머 고유 3색과 공용 게임 5색을 교차 배치해 최대 8색의 조각 팔레트를 사용합니다.
- 테마 확정 카드는 중앙 이동 뒤 0.5초 동안 두 번 깜박이며, 동작 줄이기 환경에서는 깜박임을 생략합니다.
- 토로리 코코의 진한색을 탄성 벽보다 어두운 고채도 하늘색 `#176188`로 조정했습니다.

## 1.3.24 스트리머 3색 팔레트와 게임 화면 안정화

- 다섯 스트리머 이미지에서 `진한색 / 메인색 / 옅은색` 3색 팔레트를 정의하고 Roulette 조각, Showdown 벽·미리보기 강조에 같은 역할로 연결했습니다.
- 아모레또·유레카·세나 아르벨·토로리 코코·망징이 마블은 명단 위치와 무관하게 각자의 메인색을 유지하며, 나머지 참가자는 같은 시드에서 재현되는 남은 색을 배정받습니다.
- Roulette 완료 화면은 `한 명 추가로 뽑기`를 주 동작으로 바꾸고 같은 결과 다시 보기를 제거했습니다. 멈춤 뒤 결과 알림이 레이아웃 행을 늘려 룰렛을 축소하던 문제와 남아 있던 고정 테마색도 함께 수정했습니다.
- Showdown의 찌그러진 정적 SVG 준비 화면을 제거하고, 실제 물리 미리보기는 화면에 필요한 10초·300프레임만 계산하도록 줄였습니다.

## 1.3.23 테마 프로필 로딩 최적화

- 테마 선택창의 스트리머 프로필 5장을 화면 용도에 맞춘 WebP로 교체해 총 자산 크기를 821,392B에서 258,088B로 68.6% 줄였습니다.
- 선택창에 보이는 이미지는 즉시 비동기 디코딩하고 현재 선택된 프로필에 높은 요청 우선순위를 부여합니다.
- 재방문 시에는 데이터 절약 모드를 존중하면서 브라우저 유휴 시간에 나머지 프로필을 낮은 우선순위로 준비해 `테마 교환`을 열 때의 지연을 줄였습니다.
- 프로필 경로·크기·형식을 하나의 자산 명세로 통합하고, GitHub Pages의 `/exlab/` 하위 경로와 루트 배포를 함께 검증합니다.

## 1.3.22 전체 버튼 상호작용 피드백

- 공통 셸, 테마·명단 모달, Roulette와 Showdown의 모든 보이는 버튼에 짧은 hover·press 피드백을 통일하고, reduced-motion에서는 크기 변화 없이 색 상태만 유지합니다.
- Showdown 토글의 선택 상태와 경기 시작 준비 중 잠금을 보강하고, 주 버튼 hover가 현재 스트리머 테마 팔레트를 따르도록 수정했습니다.
- Roulette 비활성 버튼의 잘못된 눌림을 제거하고, 미리보기 재생·명단 복사에 실행 중 문구와 `aria-busy`를 추가했습니다.
- 빈 기록 삭제·빈 명단 복사처럼 실행 결과가 없는 버튼은 명시적인 비활성 상태로 바꾸고, 잘릴 수 있던 segmented control의 키보드 포커스 링을 내부형으로 보강했습니다.

## 1.3.21 현재 테마 아바타 구도 조정

- 우상단 현재 테마의 원형 프로필에서 아모레또와 망징이 이미지만 10% 축소해 얼굴 윤곽이 원 안에 더 보이도록 조정했습니다.
- 원형 현재 테마 전용 배율을 분리해 테마 선택창의 카드 이미지 크기와 위치에는 영향을 주지 않습니다.

## 1.3.20 테마 선택 미리보기·확정 연출

- 테마 카드를 선택하는 즉시 공통 UI와 Showdown 경기 팔레트가 함께 바뀌어, 확정 전에 실제 적용 모습을 비교할 수 있습니다.
- 교환 창을 취소하면 직전 확정 테마로 돌아가며, 확정한 경우에만 선택을 저장합니다.
- 카드의 호버·선택 돌출 효과를 추가하고, 확정 시 다른 네 카드는 페이드 아웃한 뒤 선택 카드만 중앙에서 120px에서 160px로 확장해 2초간 유지합니다.
- 다시 테마 교환 창을 열면 다섯 카드가 각각 120px인 선택 화면으로 초기화됩니다.
- 창 바깥 스크롤을 막고, 낮은 화면에서는 스크롤바 없는 내부 목록과 가장자리 방향 표시로 모든 카드와 버튼에 접근할 수 있게 했습니다.

## 1.3.19 Roulette UX·세션 복구 안정화

- Roulette에 세션 목표, 진행 수, 완료 전후 행동과 설계 복귀 후 이어가기/종료 흐름을 복원했습니다.
- 같은 결과 다시 보기는 물리 연출만 재생하며 기록, 당첨 제외와 상품 재고를 변경하지 않습니다.
- 완료 세션을 다시 열면 직전 후보 배열, 정지 위치와 당첨 표식을 그대로 복원합니다.
- 원판 이름표와 결과 레일을 화면 크기에 맞춰 재배치하고, 소형 원판은 후보 명단과 연결된 번호로 식별합니다.
- 공통 명단은 동일 이름, 긴 이름과 최대 인원 오류를 입력 손실 없이 안내합니다.

## 1.3.18 테마 카드 프로필 구도 분리

- 테마 선택 카드의 유레카와 세나 아르벨 이미지만 기존 위치에서 10px 아래로 이동했습니다.
- 메인 화면의 원형 현재 테마 이미지는 공용 프로필 원본 위치를 유지하도록 카드 전용 오프셋을 분리했습니다.
- 이후 카드 구도를 조정해도 원형 프로필이나 다른 이미지 표면에 연쇄 적용되지 않습니다.

## 1.3.17 미리보기 명단 주기 스냅샷

- Roulette와 Showdown의 최초 미리보기 명단을 `레또`, `레카`, `세나`, `코코`, `망징`으로 통일했습니다.
- 참가자 명단을 편집해도 진행 중인 시연은 그대로 끝까지 재생하고, 가장 최근 명단은 다음 시연 주기가 시작될 때 반영합니다.
- 한 주기 안에서 명단을 여러 번 바꾸면 중간 상태로 미리보기를 재시작하지 않고 마지막 변경만 사용합니다.

## 1.3.16 Showdown 핀·테마 교환 정리

- Showdown 핀을 보랏빛이 도는 파랑으로 바꾸고, 첫 구간 끝 단독 핀까지 출발 정렬 회피 대상으로 확장했습니다.
- 우상단에는 현재 스트리머만 표시하며, `테마 교환` 버튼에서 기존 5개 프로필 카드 선택창을 다시 열 수 있습니다.
- 유레카와 세나 아르벨 프로필은 카드 안의 원래 세로 위치로 복원했습니다.

## 1.3.15 토로리 코코 하늘색 팔레트

- 토로리 코코의 테마 색상축을 파랑에서 맑은 하늘색으로 이동해 망징이의 진한 로열블루와 명확히 구분했습니다.
- 공통 UI의 강조색, Showdown 외곽 프레임과 기본 벽이 같은 공용 팔레트를 사용합니다.
- 토로리 코코의 옅고 밝은 테마 성격과 모든 텍스트 대비 기준은 유지합니다.

## 1.3.14 카페 댓글 명단 가져오기

- 공통 명단 작성창에서 `카페 댓글에서 가져오기`를 필요할 때만 펼쳐 사용할 수 있습니다.
- 카페 글 전체를 붙여넣으면 원댓글 작성자만 추출하고 대댓글은 제외한 뒤, 저장 전 명단 입력란에서 결과를 검토할 수 있습니다.
- 붙여넣은 원문은 브라우저 안에서만 처리하며 서버로 전송하지 않습니다.
- 같은 보조 입력 구조를 Roulette 단독 명단 편집에도 적용하고, 파서를 공용 플랫폼 모듈로 옮겨 이후 추가 게임에서도 재사용할 수 있게 했습니다.

## 1.3.13 유레카·세나 프로필 구도

- 유레카와 세나 아르벨의 프로필 이미지를 카드 안에서 정확히 10px 아래로 이동해 위쪽 눈 영역이 더 보이도록 조정했습니다.
- 나머지 세 테마의 구도와 모든 카드의 120px 높이는 유지합니다.

## 1.3.12 스트리머 전체 이름

- 테마 표시 이름을 `아모레또 → 유레카 → 세나 아르벨 → 토로리 코코 → 망징이`로 통일했습니다.
- 첫 테마 카드, 우상단 테마 선택기, 기본 명단과 미리보기 예시는 모두 같은 테마 원본에서 전체 이름을 가져옵니다.
- 저장용 테마 ID는 유지해 기존 선택값과 호환됩니다.

## 1.3.11 첫 테마 카드 높이

- 첫 테마 선택창의 다섯 프로필 카드를 각각 정확히 120px 높이로 고정했습니다.
- 낮은 화면에서도 카드 높이는 줄이지 않고, 선택창 내부 스크롤로 모든 테마와 시작 버튼에 접근합니다.

## 1.3.10 첫 테마 단일 세로 목록

- 첫 테마 선택창의 다섯 프로필 카드를 데스크톱과 모바일 모두 하나의 세로열로 통일했습니다.
- 표시 순서는 `아모레또 → 유레카 → 세나 → 코코 → 망징`이며, 저장용 테마 ID는 유지해 기존 선택값과 호환됩니다.
- 카드 높이와 선택창 너비를 조정해 1280×720에서도 다섯 카드와 시작 버튼을 한 흐름에서 확인할 수 있게 했습니다.

## 1.3.9 테마 벽·첫 선택·결승 표식

- Showdown의 일반 벽과 곡선 벽은 선택한 스트리머 테마의 고대비 핵심색을 사용합니다. 범퍼·핀·가이드·탄성벽·회전 막대의 역할 색은 물리 성격을 구분할 수 있도록 유지합니다.
- 기존에 테마 값만 저장되어 있던 사용자도 새 프로필 카드 선택창을 한 번 확인하도록 온보딩 완료 표식을 `v2`로 분리했습니다. 확인한 뒤에는 다시 나타나지 않고 선택한 테마는 그대로 이어집니다.
- 결승 체크 라인 오른쪽에 연결된 `FINISH` 플래그를 추가하고 모든 공과 장애물 뒤에 마지막으로 그려, 맵에 가리지 않으면서 실제 결승 위치를 정확히 가리키게 했습니다.
- 마지막 역전 카드에서는 내부 재생 배율 설명인 `0.5× SLOW`를 제거하고 선수와 역전 상태만 표시합니다.

## 1.3.8 첫 테마 선택과 Showdown 팔레트

- 처음 접속한 사용자는 exclipper에서 가져온 5개 프로필 카드를 큰 선택 화면에서 확인하고 테마를 정한 뒤 게임으로 들어갑니다.
- 기존에 테마를 저장한 사용자는 선택 화면을 다시 거치지 않으며, 이후 변경은 우상단의 작은 선택기를 사용합니다.
- 각 스트리머의 대비 검증된 다크 팔레트를 Showdown 경기 배경, 외곽 프레임, 순위표와 결과 오버레이에 연결했습니다.
- 코스와 장애물의 역할 색상은 경기 판독성을 위해 기존 규칙을 유지합니다.

## 1.3.7 작은 화면 이름 판정 영역

- 작은 방송 화면에서 Roulette와 Dart의 경계 이름표가 휠을 가리지 않도록 휠 위에 독립된 판정 영역을 예약했다.
- 모바일에서는 휠 크기를 유지한 채 세로 여백을 재배분하고, 낮은 데스크톱 화면에서는 기존 상단 여백을 활용한다.

## 1.3.6 화면 밖 추격자와 핀 안전 출발

- 선두를 따라가는 경기 화면에서 전체 2·3위가 화면 위쪽 밖에 있을 때, 실제 x방향에 맞춘 이름·순위·위쪽 화살표를 상단 가장자리에 표시합니다.
- 추격자가 화면 안으로 가까워질수록 표식이 0.82배에서 1.12배까지 커지며, 추격자가 화면 안에 들어오거나 첫 골인이 발생하면 즉시 사라집니다. 모션 감소 환경에서는 크기를 1배로 고정합니다.
- 시드 기반 불규칙 출발은 그대로 유지하면서 모든 시작 마블이 첫 번째 노란 핀 열의 중심선과 최소 10.5px 떨어지도록 재배치해, 출발 즉시 핀 위에 얹히는 자리 불이익을 제거했습니다.
- 2~10명, 참가자 수별 300개 시드로 핀 정렬 회피를 검증하고 화면 밖 표식의 순위·경계·확대·종료 조건을 자동 테스트로 고정했습니다.

## 1.3.5 헤더 스트리머 테마 선택

- 5개 스트리머 테마 선택을 공통 설정 패널에서 공통 헤더 우상단으로 옮겨 게임 선택과 나란히 배치했습니다.
- 프로필 이미지만 보이는 32px 원형 라디오로 한 번에 전환하며, 모바일에서는 24px로 축소해 게임 선택과 함께 한 줄을 유지합니다.
- 테마 상태와 저장 책임은 공통 셸에만 두고 게임 adapter의 중복 테마 전달값과 각 게임 설정 패널의 중복 선택 UI를 제거했습니다.
- 원형 선택기는 키보드 라디오 조작, 스트리머별 접근성 이름, 고대비 선택 링을 유지합니다.

## 1.3.4 GitHub Pages 정적 미러

- 기본 Vinext·Sites 빌드와 분리된 클라이언트 전용 진입점으로 같은 `ExlabApp`을 `/exlab/` 경로에 빌드합니다.
- Roulette와 Showdown의 지연 로딩, 공통 명단, 동일 이름 정책, 스트리머 테마와 로컬 저장 상태를 공개 Pages에서도 그대로 사용합니다.
- GitHub Actions가 생산 빌드와 117개 회귀 테스트를 통과한 뒤 정적 산출물을 검증하고 Pages에 배포합니다.
- 배포 검증은 `/exlab/` 자산 기준 경로, 두 게임의 동적 청크, `.nojekyll`, OG 이미지와 다섯 스트리머 프로필 이미지의 존재를 확인합니다.
- GitHub Pages는 공개 미러이며, 인증된 비공개 Sites 배포와 별개로 운영합니다.

## 1.3.3 인게임 결과 UI 통합 범위

- 게임 무대와 결과 레일을 결과 발표 전후에 계속 마운트하는 `Continuous Stage + Result Dock` 구조를 적용합니다.
- Showdown은 별도 결과 페이지로 전환하지 않고 RaceCanvas 위에서 승자 Hero를 공개하며, 기존 라이브 순위 레일이 도착 결과 레일로 이어집니다.
- Roulette은 원판과 다트를 유지한 채 당첨자 Hero가 게임 무대에서 오른쪽 최신 결과 행으로 이동합니다.
- 결과 계산과 표현 생애주기를 분리하고, 오래된 `runId`·`presentationId` 이벤트가 현재 연출을 바꾸지 못하게 합니다.
- 결과 공개 뒤에도 Showdown 미도착 마블과 골인 시간이 동일 화면에서 계속 갱신됩니다.

## 기존 통합·안정화 범위

- 공통 헤더의 게임 레지스트리에서 Roulette와 Showdown을 전환합니다.
- 공통 헤더의 `참가자 N명` 버튼에서 공유 명단 대화상자를 열며, 저장한 명단은 Roulette와 Showdown에 동시에 반영됩니다.
- 동일 이름 정책도 두 게임이 공유합니다. 기본값은 미허용이고, 허용하면 같은 이름의 각 입력 행을 삭제하거나 합치지 않고 서로 다른 참가 번호로 유지하며 선택값을 저장합니다.
- 두 게임은 `exlab:roster:v1` 공유 명단을 사용하며, 게임별 가중치·상품·조 편성·물리 설정은 서로 섞지 않습니다.
- 마지막으로 사용한 게임과 4개 스트리머 테마를 브라우저에 보존합니다. 공통 셸은 실용적인 라이트 기반을 유지하면서 선택한 프로필의 색을 제품 chrome에 적용합니다.
- Showdown 코스만 게임 전용 라이트·다크 맵 토글을 제공하고 기본값은 라이트입니다.
- 실행 중에는 게임 전환을 잠그고, 준비 상태로 돌아온 뒤 다시 전환할 수 있습니다.
- 최초에는 마지막으로 선택한 게임만 지연 로드합니다. 방문한 게임 화면은 이후 keep-alive로 마운트 상태를 유지해 전환 전 설정 초안을 보존하고, 비활성 게임에는 `active=false`를 전달해 미리보기·타이머 같은 지속 작업을 일시 정지합니다.
- 새 게임은 catalog와 공통 adapter 계약을 등록하는 방식으로 추가합니다.
- Showdown 준비 화면의 큰 홍보형 제목·장문 소개를 제거하고 게임 설정, 미리보기, 주 행동만 남겼습니다.
- 기존 Showdown(Race 레거시) 명단은 새 공통 명단이 없을 때 한 번 가져오고, 이후 공유 명단을 저장할 때 `marble-game:roster`에도 함께 기록해 이전 버전으로 롤백할 수 있게 합니다. 별도 origin의 Roulette 저장소는 자동 이전하지 않습니다.
- Showdown과 Roulette 스타일은 각각 `.showdown-game`, `.roulette-game` 범위로 격리합니다. 공통 셸은 모든 하위 서체를 `Inter` → `Pretendard` → 시스템 산세리프로 덮어써 하나의 타이포그래피를 유지합니다.
- Showdown의 스코프 루트 스타일을 복구해 라이트 맵에서도 방송 프레임과 순위표 대비를 유지하며, 데스크톱 준비 화면은 뷰포트 안에 고정하고 긴 설정만 패널 내부에서 스크롤합니다.

자세한 공통 상태·저장·게임 adapter 계약은 [EXLAB_PLATFORM_SPEC.md](./docs/EXLAB_PLATFORM_SPEC.md)를 참고하세요.

## Showdown

전체 명단을 조당 최대 10명으로 균형 편성한 뒤, 선택한 조의 마블이 시드로 만든 불규칙한 가로 배치에서 동시에 출발해 Matter.js 물리 코스를 통과합니다. 우승자를 먼저 정하는 모드는 없으며, 출발 전에 참가자를 익명 슬롯에 한 번 배정한 뒤 실제 결승 통과 순서만으로 결과를 결정합니다.

1.3.5는 1.2.3의 Showdown 물리·라이브 시계·골인 기록 계약을 변경하지 않습니다. 현재 시간은 화면이 보여주는 소수 물리 프레임을 따라가므로 FINAL MIX 슬로모션에서도 장면과 어긋나지 않으며, 당첨자 기록은 최초 결승 통과 프레임에서 고정됩니다.

## 구현 범위

- 전체 명단 최대 320명, 조당 2~10명
- 전체 인원에 맞춘 최소 조 수 자동 보정과 더 작은 조 선택
- 동일 이름 기본 미허용, 운영자 옵션으로 별도 참가 허용
- 1명 이상 N명 당첨 설정과 당첨 기준·포디엄 기준을 분리한 경기 유지
- `podiumCount = min(3, 참가자 수)`, `resultGateCount = max(winnerCount, podiumCount)`로 계산하고, 결과 게이트 인원이 화면에 모두 도착한 뒤 3초간 경기 화면을 유지한 다음 결과 전환
- 결과표를 연 뒤에도 미도착 순위는 공란으로 두고, 전체 물리 프레임을 계속 재생하며 도착 순서대로 실시간 입력
- 결과 진입 시 같은 `runId`의 최소 기록을 한 번 저장하고, 추가 도착자가 생길 때만 해당 기록을 갱신해 프레임마다 중복 이력을 만들지 않음
- `createRaceSlotAssignment`로 시뮬레이션 전에 참가자·출발 슬롯 대응을 확정하고, `RaceSimulation`이 그 매핑을 결과까지 보유하는 재현 가능한 Matter.js 물리 시뮬레이션
- `layoutSeed`로 익명 슬롯의 x좌표에 ±12px 지터를 주되 평균을 0으로 맞추고, y좌표·동시 해제·최소 36px 간격을 유지하는 불규칙 출발 배치
- 결과·당첨자·참가자 신원을 참조하는 힘, 선두 감속, 속도 덮어쓰기, 횡풍, 공간 힘장은 사용하지 않음
- 미도착 후미 마블에만 +y 방향으로 적용되는 제한형 추격 가속: 600px부터 부드럽게 시작해 1,000px에서 2위는 기본 중력의 25%, 최하위는 32%에 도달하고, 선두를 따라잡는 속도가 600px/s에 이르면 0까지 감쇠
- 기존 속도감을 유지한 채 세로 길이를 13,500px로 확장한 약 30초 코스
- 경기 구간 폭 366~774px, 중심선 x=250~660의 10개 직선 구간과 좌우 이동량이 큰 9개 S자 전환부, 4개 360° 회전 장치
- 25% 단위로 `PIN DROP → BUMPER RUN → SQUEEZE GATES → FINAL MIX`의 장애물 밀도와 구성을 바꾸고 구간 경계를 경기 화면과 미리보기에 표시
- Matter 충돌 법선과 반발계수만 사용하는 막대형 범퍼. 별도 위치·속도 덮어쓰기나 순위 기반 충격은 사용하지 않음
- 60Hz 경기 스텝을 두 번의 120Hz 물리 서브스텝으로 계산해 빠른 마블의 벽 터널링을 방지하고, 외곽 경계 이탈을 좌표 보정으로 숨기지 않음
- 범퍼 반발계수 `1.22~1.32`, 회전 막대 반발계수 `0.68~0.80`과 상향된 회전 속도
- 일부 직선 벽을 범퍼와 같은 반발계수로 설정한 탄성 벽 구간
- 장애물 성격을 색으로 구분하는 공용 5색 체계: 핫핑크=범퍼, 레몬=핀, 민트=가이드, 스카이=탄성 벽, 라벤더=회전 막대
- 코스 바탕은 라이트 모드가 기본이며 다크 모드를 선택 가능. 장애물의 의미 색상은 두 모드에서 동일
- 결승 직전 `한쪽 위험 범퍼 → 벽 방향 회전 막대 → 완만한 수축부 → 내부 폭 60px 결승 통로` 구조
- 위험 범퍼나 회전 막대에 우연히 걸린 선두만 잠시 지연되고, 다른 마블은 항상 최소 3개가 나란히 통과할 수 있는 우회 폭을 확보
- 최종 결승 회전 막대 폭 244px, 위험 경로 점유율 상한 60%. 실제 위험 점유율은 57.83%이고 상시 우회 폭은 159.59px, 마블 지름 기준 5.32개
- 핀·섬·선반·회전 바는 직선 구간에만 배치하고, 모든 경기용 직선 구간의 좌·우 벽에 최소 1개씩 중앙 유도 디플렉터가 있는지 자동 검증
- 모든 독립 충돌체 사이에 공 지름 30px보다 넓은 36px 최소 통과 폭을 강제하는 코스 검증기
- 회전 막대는 전체 회전 반경 대신 중심축에 반지름 15px 공 하나가 놓인 것으로 검사하며, 회전 팔이 주변 오브젝트 가까이 지나가는 것은 허용
- 40초 이후에만 전원에게 같은 비율로 적용되는 시간초과 방지 중력 상승. 참가자·순위·결과와 무관
- 동일 경기 재생, 새 경기 생성, 최근 결과 20개 로컬 저장
- 데스크톱 전체 순위와 모바일 상위 3명 실시간 순위. 제목에는 현재 물리 경기 시간, 각 행에는 미도착 `—` 또는 최초 결승 통과 프레임의 `MM:SS.cc` 골인 시각을 표시하고, 순위 교체를 0.2초 위치 전환으로 연결. 결과 발표의 당첨자 카드와 도착 순위에도 같은 골인 시간을 유지하며, 모바일에서는 첫 3행 밖에 있더라도 현재 가장 앞선 미도착 경쟁자를 항상 추가 표시
- 세로 가속도를 적용한 선두 추적 카메라, 0.5초 선두 변경 확인, 카운트다운, 효과음, reduced-motion 대응
- 실제 물리 이벤트로만 작동하는 지속 선두 교체, 접전, 결승 접근, 포토 피니시, 속도 트레일 연출. 다중 당첨 경기에서는 결과 게이트가 충족될 때까지 미도착 경쟁자 사이의 선두 교체를 계속 감지
- FINAL MIX(진행률 75~100%)에서 첫 완주 전 전체 1·2위 사이에 발생해 6프레임·15px 조건으로 확인된 역전만 실제 `holdStartFrameIndex` 기준 0.3초 전부터 0.2초 후까지 0.5배속·100% 확대(2.0배)로 강조하고, 겹치면 최신 이벤트로 0.5초를 갱신
- reduced-motion에서는 정상 속도·무확대 정적 큐만 표시하며 시네마틱은 물리 프레임과 결승 순서를 바꾸지 않음
- 매 프레임 바뀌는 거리·시간 수치는 `aria-live`에서 제외하고 지속 선두 교체·접전·결승 접근·포토 피니시 같은 사건만 보조 기술에 알림
- 라이트·다크 양쪽에서 공용 5색 장애물의 경계가 배경과 분리되도록 테마별 외곽선 적용
- 같은 경기 다시 보기에서 카메라와 일시 연출 상태를 함께 초기화하는 재생 에포크
- `3 → 2 → 1 → GO` 출발과 준비 화면의 10초 실제 물리 미리보기
- 준비·생성·방송 대기·경기·결과·오류 상태를 분리한 독립 실행 흐름

## 물리 결과 계약

Showdown에는 결과 선확정 모드가 없습니다.

1. 경기 생성 시 `createRaceSlotAssignment`가 `raceSeed`로 참가자와 익명 출발 슬롯의 대응을 한 번 정합니다.
2. `raceSeed`로 모든 참가자에게 공통인 물성·회전 장치 변형을 정하고, `layoutSeed`로 익명 슬롯별 ±12px x 지터를 만듭니다. 지터 평균은 0, y좌표는 동일하며 마블 간 최소 거리는 36px입니다.
3. 확정 매핑을 `simulateRace`에 전달하고 `RaceSimulation.slotToCandidateId`에 복사해 물리 프레임과 참가자 대응의 단일 근거로 사용합니다.
4. 경기 중 참가자 ID, 이름, 색상, 당첨자, 예정 결과를 읽어 힘을 바꾸지 않습니다. 실시간 거리와 미도착 순위는 공개된 제한형 추격 가속에만 사용합니다.
5. 추격 가속은 후미 마블의 +y 힘만 더하며 선두를 늦추거나 마블 속도를 덮어쓰지 않습니다.
6. 범퍼·회전 막대·탄성 벽은 Matter의 접촉 법선과 반발계수로만 공을 튕깁니다.
7. 실제 결승선 통과 순서가 당첨자와 최종 순위를 결정합니다.

같은 두 시드는 같은 배치와 물리 프레임을 재현하지만, 어떤 슬롯이나 참가자의 승리를 보장하지 않습니다.

## 현재 설계 기준

결승부의 목표는 “모두를 붙잡아 무작위로 다시 뽑기”가 아니라, 한쪽 위험 경로를 탄 선두가 잠깐 머뭇거리는 동안 열린 우회로의 후속 마블이 통과할 수 있게 하는 것입니다. 제한형 추격은 큰 격차의 후미 마블만 보조하며 결과를 참조하거나 선두를 늦추지 않습니다. 결승 진입 순위와 최종 순위의 상관관계, 선두 우승률, 격차 분포, 위험 장애물 접촉 에피소드를 함께 회귀 지표로 관리합니다.

자세한 테스트 결과와 설계 결정은 [DESIGN_FINDINGS.md](./docs/DESIGN_FINDINGS.md), 물리 변화 후보와 적용 기준은 [GAMEPLAY_VARIATION_DESIGN.md](./docs/GAMEPLAY_VARIATION_DESIGN.md), 전체 명단·조 편성·풀 패키지 계약은 [EXLAB_SHOWDOWN_SYSTEM_SPEC.md](./docs/EXLAB_SHOWDOWN_SYSTEM_SPEC.md)를 참고하세요.
